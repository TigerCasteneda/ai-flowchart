# 产品设计文档

## 一、设计目标

### 1. 复刻产品名称
AI FlowChart - 智能图表生成工具

### 2. 核心功能

| 序号 | 功能 | 具体说明 |
|------|------|----------|
| 1 | **AI 文字绘图** | 输入"用户登录流程"等描述，点击发送，自动生成图表 |
| 2 | **文档转图表** | 上传 .txt/.md/.docx 文件，AI 分析内容生成图表 |
| 3 | **基础形状绘制** | 支持矩形、圆形、菱形、三角形、太阳、云朵等图形 |
| 4 | **节点连线** | 点击两个节点自动创建带箭头的连线 |
| 5 | **拖拽编辑** | 鼠标拖拽移动节点位置 |
| 6 | **样式调整** | 修改节点颜色、大小、文字 |
| 7 | **导出功能** | 导出 PNG 图片或 JSON 数据 |

### 3. 预期使用体验
- **操作简单**：不需要学习，输入文字就能用
- **响应快速**：3-5 秒生成图表
- **结果直观**：生成的图表清晰美观
- **编辑灵活**：生成后可手动微调

## 四、技术选型

### 1. 技术栈选择

| 层级 | 技术 | 理由 |
|------|------|------|
| **前端框架** | 纯 HTML + CSS + JavaScript | 简单直接，无需构建工具 |
| **绘图引擎** | HTML5 Canvas API | 浏览器原生支持，性能好 |
| **AI 集成** | OpenRouter API | 支持多种模型，API 调用简单 |
| **后端代理** | Cloudflare Pages Functions | 隐藏 API Key，免费托管 |
| **托管平台** | Cloudflare Pages | 免费、快速、全球 CDN |

### 2. 为什么不用框架？

| 对比 | 用 React/Vue | 用原生 JS |
|------|-------------|-----------|
| 学习成本 | 需要学习框架 | 已有知识即可 |
| 代码量 | 需要配置、打包 | 直接写代码运行 |
| 功能需求 | 杀鸡用牛刀 | 刚好够用 |
| 部署难度 | 需要 build 步骤 | 直接上传文件 |

**结论**：作为学生项目，原生 JS + Canvas 足够实现所有功能，且更容易理解和调试。

## 六、技术难点与解决方案

### 难点 1：AI 返回数据格式不稳定

**问题**：AI 可能返回格式错误的 JSON

**解决方案**：
```javascript
function parseAIResponse(response) {
    try {
        // 尝试直接解析
        return JSON.parse(response);
    } catch {
        // 提取 ```json 代码块
        const match = response.match(/```json\s*([\s\S]*?)\s*```/);
        if (match) {
            return JSON.parse(match[1]);
        }
        // 最后的尝试：提取 {} 内容
        const jsonStart = response.indexOf('{');
        const jsonEnd = response.lastIndexOf('}');
        return JSON.parse(response.slice(jsonStart, jsonEnd + 1));
    }
}
```

### 难点 2：节点自动布局

**问题**：AI 返回的数据可能没有坐标，需要自动排列

**解决方案**：
- 简单布局：按顺序横向排列
- 层级布局：根据连线关系计算层级
- 力导向布局：模拟物理引力自动散开

### 难点 3：Canvas 性能

**问题**：节点过多时绘制变慢

**解决方案**：
- 只重绘变化的部分
- 使用离屏 Canvas 缓存
- 限制最大节点数量

### 难点 4：文档解析

**问题**：.docx 文件格式复杂

**解决方案**：
- 使用 JSZip 解压 .docx 文件
- 解析 document.xml 提取文字
- 限制长度后发送给 AI
